# Verification: Observer Use Case, `NoTranslation` Strategy

Verifies [UseCases.md](UseCases.md)'s use case 3 — one process ([observer/main.go](observer/main.go)) reporting metrics about two other applications it observes, each with its own `job`/`instance` identity — under the SDK's **`NoTranslation`** strategy, using the `krajo/job-instance-persistence` fork's Options B, C, and C1 (rebuilt against commit `78a1b6d`), alongside **Current** (no gates). Companion to [verification-observer-default-translation.md](verification-observer-default-translation.md).

**Implementation and setup**: identical to the default-translation report, with `OBSERVER_NO_TRANSLATION=true`. App 1 — `service.name="my_service1"`, `service.instance.id="my_id1"`, `job="my_job1"`, `instance="my_instance1"`, counter value `1` (App 2: same shape with `_2`/`2`). Scraped as `job_name="observer_job"`, target `observer:9464`, `honor_labels: true`, egress via `prometheus_remote_write`. All four columns were actually run, Prometheus's storage wiped between captures. Same methodology note as the default-translation report applies: the inactive `my_job`/`oteljob:9464` scrape target's benign `up=0` + synthesized `target_info` is excluded from the tables below.

## Footnotes

[^1]: Same collision mechanism as `verification-notranslation.md`'s footnote 2, recurring here per observed app: `CreateResource` derives `service.name="my_job1"`/`service.instance.id="my_instance1"` from App 1's per-series labels (Current), or additionally stores the namespaced pair alongside them (B) — the pair itself, stored under different keys entirely, is untouched by what happens next. `AddTargetInfo` then overwrites the dotted keys with the app's own declaration, since under `NoTranslation` that declaration arrives already spelled `service.name`/`service.instance.id`.

[^2]: This is the same central finding as `verification-notranslation.md`'s footnote 3, confirmed again here: Option C's covered-name recognition only matters when a Resource's declared identity would otherwise arrive *flattened* (`service_name`/`service_instance_id`) — which only happens under the default translation strategy. Under `NoTranslation` there's no flattened spelling to recognize, so `addTargetInfoWithCoveredNameRecognition` reduces to the same single-spelling `attrs.PutStr` the old (C1) verbatim-copy loop already did, and C/C1/B all converge on the same output once the collision is accounted for. Contrast with [verification-observer-default-translation.md](verification-observer-default-translation.md), where this same commit produces a real, and counterproductive, behavioral change for this use case.

[^3]: See `verification-notranslation.md`'s footnote 1 for the root cause (bare `promhttp.Handler()`/`HandlerFor` never enables OpenMetrics) and its footnote 4 for why the collector's `prometheus_remote_write` exporter re-adds a `_total` suffix the design document's own table doesn't predict for this scenario.
