Verification: One Counter, Default Translation Strategy

Re-verifies “End-to-End Comparison: One Counter, Default Translation Strategy” against a real running system, using the custom otelcol-custom collector built from the krajorama/opentelemetry-collector-contrib branch krajo/job-instance-persistence (see otelcollector/), rebuilt against commit 78a1b6d (“Add POC option C1”). That branch implements Options A/B/C/C1 as four mutually-exclusive alpha feature gates, off by default:

  • Receiver: receiver.prometheusreceiver.jobInstanceOption{A,B,C,C1}
  • Exporter: exporter.prometheusremotewrite.jobInstanceOption{A,B,C,C1}

Shown below: Current (today’s collector behavior, no gates enabled) plus B, C, and C1. Option A is omitted — four option columns plus Current made the tables too wide, and its bare job/instance resource attributes aren’t a shape that makes sense in the OTel data model to begin with. Option A’s own results are unaffected by this update and remain available in git history.

Option C1 is new: as of commit 78a1b6d, Option C’s receiver-side (AddTargetInfo) gained “covered-name recognition” — it now recognizes target_info’s flattened service_name/service_namespace/service_instance_id labels as declaring the same identity as their dotted spelling, not just the literal dotted form. Option C1 is Option C without that recognition — i.e., exactly the old Option C behavior this report previously documented. The two share identical exporter-side (OTLP → Prometheus) logic; they differ only in what the receiver populates.

Setup: oteljob app — resource service.name="my_service", service.instance.id="my_id"; meter foo; Float64Counter("received_samples") with attribute a.a="b"; default SDK translation strategy (no -no-translation). Scraped by the collector as job_name="my_job", target oteljob:9464. Egress via the collector’s prometheus_remote_write exporter to the custom-built Prometheus (prometheus/, branch krajo/debug-otlp-rw-endpoint). All four columns were actually run in the compose stack (OTELCOL_FEATURE_GATES=<gate names> docker compose --profile standalone up -d --force-recreate oteljob otel-collector prometheus), with Prometheus’s storage wiped between captures; nothing here is inferred from source alone.

Net effect Scrape identity (job/instance) wins on every series; the app’s declared identity survives only as target_info metadata. Same wire output as Current; the OTLP Resource additionally carries an explicit namespaced pair, invisible on the wire.6 This is the first configuration in this whole set of reports that achieves true declared-first behavior under the default translation strategy. received_samples_total is keyed by the app’s own service.name/service.instance.id, and the scrape’s job/instance are demoted to queryable target_info metadata — the reverse of every other column. Reproduces the gap the original report flagged: the declared-identity check never fires because service.name/service.instance.id never arrive under that spelling, so the output is indistinguishable from Current and B.
