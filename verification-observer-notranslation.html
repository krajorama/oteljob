Verification: Observer Use Case, NoTranslation Strategy

Verifies UseCases.md’s use case 3 — one process (observer/main.go) reporting metrics about two other applications it observes, each with its own job/instance identity — under the SDK’s NoTranslation strategy, using the krajo/job-instance-persistence fork’s Options B, C, and C1 (rebuilt against commit 78a1b6d), alongside Current (no gates). Companion to verification-observer-default-translation.md.

Implementation and setup: identical to the default-translation report, with OBSERVER_NO_TRANSLATION=true. App 1 — service.name="my_service1", service.instance.id="my_id1", job="my_job1", instance="my_instance1", counter value 1 (App 2: same shape with _2/2). Scraped as job_name="observer_job", target observer:9464, honor_labels: true, egress via prometheus_remote_write. All four columns were actually run, Prometheus’s storage wiped between captures. Same methodology note as the default-translation report applies: the inactive my_job/oteljob:9464 scrape target’s benign up=0 + synthesized target_info is excluded from the tables below.
